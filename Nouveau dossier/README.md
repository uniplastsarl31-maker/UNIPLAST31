# UNIPLAST — متجر فرنسي جاهز لـ Netlify

الكتالوج الأصلي: **350 منتجًا**، أُعيد ترتيب عائلاته في **8 عائلات** كما طلبت، مع إبقاء العائلات الخاصة أو المخفية. ملف الاستيراد الأصلي يحتفظ بالعائلات القديمة للتتبع. واجهة فرنسية متجاوبة، سلايدر للرئيسية ولكل عائلة، تخفيضات بارزة، تعريف بالشركة واقتراحات الزبائن. الشعار وصور المنتجات الأصلية محفوظة.

## النشر على Netlify

تشغّل هذه النسخة الواجهة وخدمة المتجر والحفظ داخل مشروع Netlify نفسه، بواسطة **Netlify Functions + Blobs**. لا تحتاج إلى Render أو Supabase لهذا المسار.

1. ارفع ملفات المصدر المصححة إلى **جذر** مستودع GitHub المرتبط بالموقع. يكون `netlify.toml` بجانب `package.json`.
2. إعدادات البناء: `pnpm run build:netlify`، مجلد النشر `dist-netlify`، مجلد الوظائف `netlify/functions`، Node.js **24**. الإعدادات موجودة في `netlify.toml`.
3. في **Environment variables** في Netlify: أضف `AWS_LAMBDA_JS_RUNTIME` بقيمة `nodejs24.x`، و`UNIPLAST_SETUP_KEY` بمفتاح خاص تختاره من **24 إلى 256 حرفًا**. يجب أن يتاح المفتاح لنطاق Functions. لا تضعه في GitHub أو متغير يبدأ بـ VITE_.
4. أعد النشر. افتح **Espace de gestion**، وأدخل مفتاح التثبيت واختر كلمة مرور المسؤول من 12 حرفًا على الأقل. بعد الإعداد الأول تستخدم كلمة المرور فقط. أضف الزبائن من **Clients agréés** بالهاتف ورمز من ستة أرقام.

الدليل الكامل: [NETLIFY-FR.md](docs/NETLIFY-FR.md). رفع `dist` وحده لا يشغّل قاعدة البيانات. الحد في نسخة Netlify هو **4 ميغابايت للصورة، و20 ميغابايت للكتالوج العام أو الفيديو**.

البيانات مشتركة بين هواتف زبائن الموقع نفسه، وتبقى بعد إعادة النشر. قاعدة الكمبيوتر لا تنتقل تلقائيًا إلى الموقع. يستورد أول تشغيل على Netlify الكتالوج الأصلي فقط؛ لا يعيد زرعه فوق تعديلاتك. بيانات Deploy Preview مستقلة عن المتجر المنشور.

## إدارة المتجر

**Clients agréés**: الاسم والهاتف والرمز، دون تسجيل أو تفعيل بريد للزبون. الأكواد وكلمة مرور المسؤول محفوظة بتجزئة scrypt مع ملح؛ لا تعرضها قائمة الزبائن. تغيير رمز العميل أو تعطيله يلغي جلساته السابقة. كلمة مرور المسؤول تتغير في **Réglages → Mot de passe du responsable**.

**Réglages**: صور السلايدر وارتفاعه وتكبير الصورة ومدة الانتقال، النص التعريفي بالشركة، الهاتف وFacebook وWhatsApp والكتالوج PDF. لكل عائلة سلايدر مستقل. **Suggestions clients** لاقتراحات الزبائن الخاصة بالإدارة.

الأسعار مخفية عن الزائر افتراضيًا، ويكشفها دخول العميل المعتمد. التخفيضات والمواسم والمنتجات المقترحة تُدار من الواجهة. الفاتورة تحتفظ بالأسعار وقت الطلب، ويمكن إعداد PDF ومشاركته يدويًا. لا توجد مدفوعات إلكترونية أو رسائل تُرسل تلقائيًا.

## التشغيل على الكمبيوتر

فك المشروع الكامل، وشغّل **RUN.BAT → 1**. يلزم Node.js **22.18 أو أحدث**. أبقِ `server` و`dist` بجانب ملف التشغيل. في أول مرة تختار كلمة مرور المسؤول؛ لا توجد كلمة مرور افتراضية.

الحفظ المحلي في `.uniplast-data`. أغلق البرنامج بالخيار **0** ثم انسخ هذا المجلد كاملًا للنسخ الاحتياطي الخاص. لا ترفعه إلى GitHub أو ترسله للزبائن. عنوان 127.0.0.1 خاص بالكمبيوتر؛ زبائن الإنترنت يستخدمون رابط Netlify.

شرح بقية الإدارة والتشغيل: [UTILISATION-FR.md](docs/UTILISATION-FR.md).

## البناء والتحقق

```sh
pnpm install --frozen-lockfile
pnpm build:netlify
pnpm test
pnpm test:local
pnpm test:netlify
```

`build:netlify` يولد `dist-netlify` والملفات الخاصة بالخادم في `server/generated`. لا تُضمَّن بيانات الأسعار في ملفات الواجهة العامة. Netlify يبني وينشر الوظائف من المصدر خارج مجلد النشر العام.

`pnpm build` يحافظ على مخرجات الكمبيوتر في `dist` ومخرج الويب الاختياري القديم في `out`. مسار Supabase القديم ما زال موجودًا للتوافق؛ ليس مطلوبًا لإعداد Netlify أعلاه.

اختبارات Netlify تستخدم تخزينًا بديلًا معزولًا، وتشمل استمرار الحفظ، تعارض الكتابات، تزامن الطلبات، المخزون، إبطال الجلسات، خصوصية الملفات وحد الرفع. نجاح الاختبار المحلي لا يؤكد النشر الفعلي. الحالة الحالية في [DEPLOYMENT-STATUS.md](docs/DEPLOYMENT-STATUS.md).

بيانات التسليم خالية من العملاء والطلبات وكلمات المرور التجريبية. تبقى **33 أسعار ناقصة** بعد تحديث الأسعار السابق. المنتجات الجديدة متوفرة افتراضياً، ويمكن للإدارة تحديد عدم التوفر والمخزون؛ لا توجد تخفيضات أو مبيعات أو مخزون مختلق. ملف CSV الأصلي لم يتغير.
